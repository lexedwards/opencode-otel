# OTLP exporter compatibility

Tested with Bun 1.4.0, OpenTelemetry exporter packages 0.222.0, and `bun test` on 2026-09-24. `test/exporter-compatibility.test.ts` imports and constructs trace and metric exporters for each transport and shuts them down without exporting. All six constructors passed. HTTP/protobuf and HTTP/JSON are wired in the plugin; gRPC remains reserved. This does **not** test network delivery, TLS handshakes, Collector interoperability, or OpenCode startup.

| Transport | Trace / metric package suffix | Endpoint | Headers | TLS / mTLS | Timeout / compression |
| --- | --- | --- | --- | --- | --- |
| HTTP/protobuf | `otlp-proto` | Explicit full `/v1/traces` or `/v1/metrics` URL; generic env endpoint appends path | `headers` object or standard OTLP env headers | `httpAgentOptions` (`ca`, `cert`, `key`) or standard certificate/client certificate/client key env files | `timeoutMillis`, `compression: CompressionAlgorithm.GZIP` / `NONE`; standard OTLP env vars |
| HTTP/JSON | `otlp-http` | Same HTTP rules | Same HTTP rules | Same HTTP rules (Node HTTP implementation) | Same HTTP rules |
| gRPC (experimental on Bun) | `otlp-grpc` | Host:port or `http(s)://host:port`; path ignored | `metadata` (`@grpc/grpc-js` Metadata), not `headers`; standard OTLP env headers become metadata | `credentials` (`ChannelCredentials.createSsl(ca, key, cert)` or `createInsecure()`); standard OTLP certificate env files | `timeoutMillis`, `compression: CompressionAlgorithm.GZIP` / `NONE`; standard OTLP env vars |

An HTTP signal-specific endpoint is used as-is; a generic HTTP endpoint appends `/v1/{signal}`. gRPC uses either endpoint without adding a path. Constructing an exporter without an explicit URL can use the SDK's localhost fallback: our plugin must **never construct** an exporter for a signal without an explicit or inherited endpoint. Supply normalized explicit URLs even where the exporter also reads the environment. Generic `OTEL_EXPORTER_OTLP_PROTOCOL` and signal-specific protocol variables select a transport in the plugin, not in these individual exporter constructors.

Normalized per-signal configuration includes protocol, endpoint, redacted headers/TLS markers, timeout, compression, and applicable batching or periodic metrics settings. Private resolved header values and PEM contents are separate from printable configuration. For each OTLP setting: plugin option > signal-specific `OTEL_EXPORTER_OTLP_{TRACES|METRICS}_*` > generic `OTEL_EXPORTER_OTLP_*` > default. The effective HTTP endpoint gets a signal path only for a generic endpoint; explicit option endpoints are treated as full URLs if signal-specific. Headers from standard environment variables are parsed case-insensitively, with specific entries overriding generic; option headers override both. HTTP certificate fields refer to PEM file paths in standard OTEL env variables; plugin secret values use `{env:NAME}`. For gRPC, convert resolved headers to Metadata, certificates to ChannelCredentials, and reject endpoint paths rather than relying on upstream's warning-and-ignore behavior. Reject incomplete certificate/key pairs. No implicit localhost endpoint.

The HTTP exporter uses Node `http`/`https` agent options, not browser `fetch`; gRPC's `@grpc/grpc-js` support targets Node.js. TLS inputs and constructors are documented by the installed package types; Bun support of the actual transport is unverified. No Collector, SDK service, OpenCode server, or provider was launched.
